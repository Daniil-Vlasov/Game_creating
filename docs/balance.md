# Баланс боя — итерация 1 «Глубина боя» (v0.2.0)

Источник цифр — `src/data/enemies.json`, `cards.json`, `combinations.json`, `spells.json`.
Этот документ — спецификация для @coder и обоснование для @qa-reviewer.

## 1. Порядок хода

1. Над врагом видно **намерение** (иконка + число, уже с учётом buff и ярости, которые будут в момент удара).
2. Игрок играет 1–5 рун → Атака и Щит (формула без изменений).
3. Атака игрока сначала снимает **Щит врага**, остаток — по HP врага. HP ≤ 0 → победа (враг не действует).
4. **Действие врага** (шаг «enemyAct»):
   1. Щит врага (если был) сгорает.
   2. Если `turn ≥ rage.from` — `rage += rage.step`.
   3. Выполняется намерение (см. таблицу ниже). Урон проходит через Щит игрока.
   4. Щит игрока сгорает.
5. Добор руки до лимита. Затем, если действие было `curse`, — проклятие на руны **новой** руки.
6. Проверка фазы (только у босса) → выбор следующего намерения → показ.

`turn` — номер розыгрыша игрока в этом бою, с 1. Сброс рун ход не тратит.

## 2. Схема действий

```jsonc
"actions": {
  "mode": "cycle",            // cycle — по кругу list[0], list[1]…; weighted — случайно по weight
  "list": [ { "type": "attack", "value": 35 }, { "type": "block", "value": 80 } ]
}
```
- `weighted`: одна и та же запись списка не выбирается дважды подряд (сравнение по индексу).
- Первое намерение боя: `cycle` — `list[0]`; `weighted` — случайное.
- Босс: вместо `actions` — `phases: [{ from, title, onEnter?, actions }]`. Активна фаза с наименьшим
  `from`, для которого `hp / maxHp ≤ from`. Фазы идут **только вперёд** (лечение не возвращает).
  Проверка — на шаге 6, т.е. уже объявленное намерение всегда выполняется честно. При входе в фазу:
  баннер `title`, мгновенно применяется `onEnter` (не тратит ход), цикл новой фазы начинается с `list[0]`.
- Поле `attack: [min,max]` **оставлено для совместимости** (старый `rollIntent`), новым кодом не используется.
  Удалить после перехода BattleScene на `actions`.

**Урон одного удара** = `value + buff + rage`. Щит игрока поглощает удары по очереди и тратится.

| type | Поля | Семантика |
|---|---|---|
| `attack` | value | Один удар. |
| `heavy` | value | Как `attack`, но телеграф: красная иконка, «Тяжёлый удар», тряска/звук при объявлении. Механически отличие только в числе. |
| `block` | value | Враг получает Щит = value (не суммируется со старым — старый сгорел на шаге 4.1). Поглощает Атаку игрока на **следующем** розыгрыше, остаток сгорает на следующем действии врага. Урона нет. |
| `curse` | count, value? | Если есть value — сначала удар (как attack). После добора: `count` случайных **непроклятых** рун новой руки получают флаг «проклята». Сила проклятой руны в подсчёте = 0 (стихия остаётся, для комбинаций Восхождение/стихий используется её настоящая Сила — меняется только вклад в Силу Атаки/Щита). Флаг снимается со всех рун после следующего розыгрыша (сыграны они или нет). Сброс проклятых рун разрешён — это и есть ответ игрока. |
| `buff` | value | `buff += value` навсегда до конца боя. Урона нет. |
| `heal` | value | HP врага += value, не выше max. Урона нет. |
| `steal` | gold, value | Удар value. Если после Щита урон по герою > 0 — герой теряет `min(gold, золото)`. Если Щит поглотил удар целиком — «Кража сорвана!». Золото не возвращается. |
| `multi` | hits, value | `hits` отдельных ударов по `value + buff + rage` каждый (buff и ярость действуют на **каждый** хит — в этом угроза серии). |

Показ намерения: `attack/heavy` — итоговое число; `multi` — «3×38»; `curse` — «⛧2 · 40»; `steal` — «🗡30 · 3 зол.»;
`block/heal/buff` — значение. Подсказки — `strings.json → intents.<type>.hint` (плейсхолдеры `{v} {n} {g}`).

## 3. Правило темпа: Ярость

Выбрана **ярость**, а не лимит розыгрышей. Параметры — `enemies.json → pacing` и `rage {from, step}` у врага.

С хода `from` перед каждым действием врага `rage += step`; ярость прибавляется к каждому удару.
- Обычные враги: `from = 5` (цель 4–6 ходов: укладываешься — ярости почти нет).
- Лич: `from = 9` (цель 8–10).

Почему ярость:
- Лимит ходов даёт мгновенный и неинтуитивный проигрыш «на 0 HP-урона»; ярость — плавное давление, видимое в числе намерения.
- Ярость усиливает ключевое решение «Атака или Щит»: затянул — придётся играть Бастион вместо Смерча, бой затягивается ещё сильнее. Слабая сборка тонет в спирали — это и есть хардкор.
- Работает с уже существующими элементами (Щит игрока, намерение), не требует нового UI, кроме метки «Ярость +N».

## 4. Изменения чисел

| Враг | HP было → стало | Урон было → стало | Ярость | Награда |
|---|---|---|---|---|
| Слизень | 80 → 450 | 8–12 → 35/45, щит 80, лечение 60 | 5 / +10 | 6 |
| Гоблин | 150 → 800 | 12–18 → 45, нож 30 + кража 3, тяжёлый 90 | 5 / +20 | 7 |
| Волк | 250 → 1000 | 18–26 → 2×35, усиление +8, 3×30, 65 | 5 / +16 | 8 |
| Призрак | 380 → 1400 | 28–40 → проклятие 2 + 40, 75, щит 250, тяжёлый 130 | 5 / +12 | 10 |
| Лич | 600 → 3600 | 42–62 → фазы (ниже) | 9 / +15 | 20 |

Лич: **I (100–66 %)** «Шёпот праха»: проклятие 2+40 → удар 70 → проклятие 3+30 → щит 300.
**II (66–33 %)** «Пепельный гнев»: 70 → тяжёлый 120 → проклятие 2+45 → тяжёлый 140.
**III (< 33 %)** «Ярость Лича»: при входе +15 ко всем ударам; 3×35 → тяжёлый 130 → лечение 250.

`heroMaxHp = 80`, `campfire.healPercent = 30`, цены заклинаний и экономика — **без изменений**:
по симуляции рычагов HP врагов и урона достаточно; кража гоблина уже давит на экономику.

Почему HP выросли в 4–6 раз: раньше одна комбинация (Смерч ≈ 250) убивала слизня с одного хода.
Теперь сырая колода даёт 100–250 Атаки за ход, т.е. слизень — 3–5 ходов, а дальше без
заклинаний-множителей бой упирается в ярость.

## 6. Симуляция боёв и забега

Монте-Карло (1000 забегов на сценарий), ИИ: перебирает все подмножества руки, максимизирует
`мин(Атака, HP врага) + 1.3 × мин(Щит, входящий урон)`; **без сбросов**, на кострах всегда отдых,
события: таверна +15, бард +8, алтарь/идол пропуск. Ходы и урон — бой с полного HP.

Сценарии заклинаний (что куплено к бою):
- **нет** — ничего;
- **защитный** — Гоблин: Кам. кожа; Волк: +Гимн; Призрак: +Приливный оберег; Лич: +Мировое древо;
- **типичный** — Гоблин: Гимн; Волк: +Кам. кожа; Призрак: +Уголь; Лич: +Две луны;
- **сильный** — Гоблин: Гимн; Волк: +Уголь; Призрак: +Сердце дракона; Лич: +Две луны.

Ходов на бой / урон по герою за бой:

| Враг | нет | защитный | типичный | сильный |
|---|---|---|---|---|
| Слизень | 4.5 / 11 | 4.5 / 11 | 4.5 / 12 | 4.5 / 12 |
| Гоблин | 6.5 / 25 | 6.5 / 19 | **4.0** / 22 | 4.0 / 22 |
| Волк | 8.5 / 97 | 5.1 / 27 | **5.1** / 29 | 3.9 / 28 |
| Призрак | 12.3 / 165 | 8.0 / 38 | **6.3** / 35 | 2.9 / 26 |
| Лич | 21.5 / 1177 | 13.2 / 109 | **10.2** / 91 | 4.9 / 47 |

Исход забега (HP 80):

| Сценарий | Победа | Где гибнет |
|---|---|---|
| нет | 0 % | Гоблин 8 %, **Волк 58 %**, Призрак 32 %, Лич 2 % |
| защитный | 19 % | Гоблин 4 %, Волк 11 %, Призрак 25 %, Лич 42 % |
| типичный | 24 % | Гоблин 7 %, Волк 11 %, Призрак 17 %, Лич 42 % |
| сильный | 48 % | Гоблин 7 %, Волк 13 %, Призрак 10 %, Лич 21 % |

Критерии брифа:
- Обычный враг 4–6 ходов при типичной сборке — да (4.0–6.3; слизень 4.5 без заклинаний). Босс 8–10 — 10.2.
- Без заклинаний забег проигрывается к 3-му врагу (Волк, точка 6 из 12); до Лича доходит 2 %.
  Против нынешних ~100 % побед — хардкор. Каждые 1–2 заклинания-множителя дают ощутимый шаг.
- Победа редкая: 20–25 % для «средней» сборки у ИИ без сбросов; живой игрок со сбросами и
  событиями (алтарь — редкое заклинание) — ориентир 25–35 %, с идеальной сборкой ≈ 50 %.
- Узкое место — **Волк**: между Гоблином и Волком только бард (+8 HP). Если плейтест покажет
  «стену», первый рычаг — `wolf.rage.step` 16 → 12 или `healPercent` 30 → 35.

## 7. Что проверить в плейтесте
- Слизень не должен казаться «губкой»: если 4–5 ходов скучны — HP 450 → 380.
- Проклятие призрака: при 2 проклятых из 8 рун у игрока должен оставаться розыгрыш (сброс 3 за бой).
- Лечение Лича в фазе III (250) + ярость с 9-го хода — затяжной финал должен ощущаться «гонкой».
